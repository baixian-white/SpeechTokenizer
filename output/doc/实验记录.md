诚实 caveats：

- **LCA 微调没有改善信道扰动鲁棒性**——这是实验三的核心目标之一，但严格鲁棒性分析（base_degradation - lca_degradation 跨 12 个 L × 4 扰动条件单元）显示所有 6 个客观指标的平均 robustness_improvement 都接近 0 或微负。**绝对质量改善（mel_l1 -6%、STOI +0.016）来自 random-L 训练目标，不是 ChannelSim 训练目标**
- 可能原因：训练扰动概率过低（p_drop 平均 0.008、p_sub 平均 0.0012）、previous-index replacement 在低 dropout 率下几乎不破坏信号、GAN 训练偏向听感而非鲁棒性
- 当前评估只在 8 条 train-clean 同源样本上做，不代表通信信道场景或泛化集
- 没有运行 ASR，没有 WER/CER 数据
- 训练过程中 dev/full_mel 在 step 17500 触底（1.013），dev/comm_mel 在 step 30000 触底；中期波动较大，generator_grad_norm 末段升高（cosine 收尾段失稳信号）。论文需要诚实写"best-step selection"，不能写"训练越久越好"
- LCA 在 dev/full_mel 全深度无扰动场景下不优于 Base，承袭实验二 distill30 的 codebook 利用率不健康问题
- **建议把 LCA 论文叙述方向从"信道感知鲁棒性"调整为"random-L 多负载操作点统一训练"**，并在 limitations 段落明写鲁棒性目标未达成的原因，作为 future work（提高扰动概率 / 引入 consistency loss / 使用 mask token）

Base vs LCA v2 评估摘要（fixed_sample_list 8 条 × 3 L × 5 channel × 2 model = 240 评估对，ChannelSim seed 在 (sample, L, channel) 级别确定，Base/LCA 共享）：

绝对改善（LCA v2 - Base，平均跨 15 cell）：

| 指标 | Δ 平均 |
|---|---:|
| Δmel_l1 ↓ | -0.045（LCA 改善 ~4.5%）|
| Δstoi ↑ | +0.012（全 15 cell 一致提升）|
| Δpesq_wb ↑ | +0.011 |
| Δsi_snr_db | -0.39 dB（LCA 略劣 —— clean 条件下的代价）|

**严格鲁棒性分析（核心目标）**：12 个 (L, 4 个扰动条件) 单元的聚合，`robustness_improvement = base_degradation - lca_degradation`，正值 = LCA 退化更小。

| 指标 | v1 mean | v2 mean | LCA 更鲁棒 cell（v1）| LCA 更鲁棒 cell（v2）|
|---|---:|---:|---:|---:|
| **mel_l1** | -0.0003 | **+0.0055** | 3/12 | **12/12** |
| **pesq_wb** | -0.002 | **+0.015** | 7/12 | **10/12** |
| **stoi** | -0.0001 | **+0.0023** | 6/12 | **9/12** |
| si_snr_db | -0.018 | +0.051 | 4/12 | 7/12 |
| corr | -0.0003 | +0.0010 | 5/12 | 7/12 |
| wave_l1 | ~0 | ~0 | 6/12 | 7/12 |

**v2 在所有 6 个指标上的 robust_imp 都正向**（v1 全是负或近 0）—— 鲁棒性目标达成。最显著：mel_l1 上 12/12 cell 比 Base 更鲁棒；pesq_wb 上 10/12；stoi 上 9/12。

代表性 cell：

- **L=3 dropout-mid**：PESQ-WB 退化幅度 base +0.208 → lca +0.161（**LCA 退化少 22%**）
- **L=3 dropout-high**：mel_l1 退化幅度 base +0.088 → lca +0.072（**LCA 退化少 18%**）
- **L=1 dropout-high**：mel_l1 退化幅度 base +0.052 → lca +0.044（LCA 退化少 16.7%）

诚实 caveats：

- **v2 在 clean 条件下 si_snr_db 略劣于 Base**（每 L 大约 -0.3 到 -0.6 dB），是为换取扰动鲁棒性付出的代价。论文里要诚实写
- 当前评估只在 8 条 train-clean 同源样本上做，不代表通信信道场景或泛化集
- 没有运行 ASR，没有 WER/CER 数据
- 没在 p > 0.10 / p_sub > 0.03 的更强扰动下测过
- v1 的负面结果**不要删**——v1 → v2 的对比本身是论文中可发表的 ablation：弱扰动训练（p ≤ 0.005-0.03）不足以产生鲁棒性，需要 5-6× 强扰动 + 显式 consistency loss

**v1 留作 ablation 对照**，新加的 LCA v2 是当前 SCIT-Speech-LCA 的官方版本。后续实验四（baseline 对比）应使用 v2。

ffmpeg 安装要点（已固化在 conda env）：
- 装 ffmpeg 7.1 时遇到 `STATUS_ENTRYPOINT_NOT_FOUND` (exit -1073741511)，DLL 入口点缺失
- 降级到 **ffmpeg 6.1.2** 解决（含 libopus 支持，9.1 MB）
- 命令：`conda install -n speechtokenizer -c conda-forge ffmpeg=6.1 -y`
- 注意：speechtokenizer env 缺 `conda-meta/history`，需先 `touch C:\Users\Windows11\.conda\envs\speechtokenizer\conda-meta\history`
- ffmpeg 6.1.2 的 conda-forge build **没有** AMR-WB encoder，AMR-WB baseline 因此被迫跳过

核心结果（SCIT-Speech-LCA v2 vs 全 baseline，同码率对照）：

| 操作点 | 最佳 baseline (mel_l1/stoi/pesq/WER) | SCIT-LCA (mel_l1/stoi/pesq/WER) |
|---|---|---|
| 500 bps | DAC n_q=1: 1.98 / 0.61 / 1.05 / 0.92 | **L=1: 1.15 / 0.80 / 1.35 / 0.46** |
| 1000 bps | DAC n_q=2: 1.45 / 0.73 / 1.15 / 0.31 | **L=2: 0.92 / 0.86 / 1.71 / 0.19** |
| 1500 bps | DAC n_q=3: 1.20 / 0.80 / 1.27 / 0.15 | **L=3: 0.86 / 0.88 / 1.89 / 0.14** |

**最有冲击力的对照**：SCIT-LCA L=3 (1.5 kbps) 的 WER = 0.142，**比 Opus 6 kbps 的 WER = 0.147 还略低**——SCIT 用 1/4 带宽达到与 Opus 相同的可懂度。mel_l1 上更是 2.6× 优势（0.86 vs 2.24）。

PCM 上界给的 WER = 0.075 是 Whisper 在这 8 条样本上的固有错误率；所有方法的 WER 都受这个下界限制，方法间差异应读作"相对于 PCM 的退化幅度"。

诚实 caveats：

- 只在 8 条 train-clean 同源样本上评估，未覆盖 test-other / 跨语料库
- Whisper base.en 自身 WER ~7.5% 是测量噪声地板
- **AMR-WB 仍然缺**（最直接的传统语音 codec）；后续如需补需 build ffmpeg from source 加 `--enable-libvo-amrwbenc`，或用 gyan.dev 完整版 ffmpeg
- Opus 1.5/3 kbps 没测（libopus 实用 wideband 下限 ~6 kbps）
- 没有主观 MOS / AB 听测
- **SCIT 不超 Opus 在 12+ kbps、不超 DAC 在 6+ kbps**——只在 500-1500 bps 这个 regime 占优，论文 framing 必须诚实
- DAC 训练目标含音乐 + 语音；SCIT 仅语音。低码率上 SCIT 占优可能部分来自 domain 专门化
- 论文叙述：SCIT 打开了一个低负载 shared-codebook 操作区间，**不是** "全面超过 codec"

- 没有主观 MOS / AB 听测

### 4.5 已知 caveats

#### 4.5.1 旧 distill30 run 在 disk-full 后续训出现异常

`..._distill30_retrain_20260528_..._aborted_diskfull_resumed_div` run 在 disk-full + 整盘迁移 + `--continue_train` 后出现 dev/mel 异常退化（迁移前 step 47500 dev/mel = 3.20，续训后同 step 退化到 3.80）。原因未深究，但**强烈建议：迁移过的 run 不要使用 `--continue_train`，应该新开 run 从头训练**。当前 run 就是新开 run。

#### 4.5.2 codebook 利用率不健康（重要）

当前 run 的 RVQ codebook usage 指标（32 样本统计）：

| Layer | used | usage_rate | perplexity | dead_code_ratio | top1_freq |
|---:|---:|---:|---:|---:|---:|
| 1 | 179 | 17.48% | 130.0 | **82.52%** | 5.0% |
| 2 | 244 | 23.83% | 188.3 | **76.17%** | 3.75% |
| 3 | 273 | 26.66% | 231.2 | **73.34%** | 1.75% |

对比原 distill120 (旧 exp2) 的 usage：

| Layer | distill120 used / dead | distill30（当前）used / dead |
|---:|---|---|
| L1 | 180 / 82.42% | 179 / 82.52% |
| L2 | 972 / 5.08% | 244 / 76.17% |
| L3 | 975 / 4.79% | 273 / 73.34% |

现象与机制：

- **L1 死码率没有改善**（82.4% → 82.5%）：L1 死码可能是 RVQ 结构性问题（L1 主要承担帧级语义离散标签，少量码字够用），不是 distill_loss_lambda 调整能解决
- **L2/L3 死码率明显恶化**（5% → 73-76%）：distill_lambda 从 120 降到 30 后，L1 不再被强制对齐到狭窄语义子空间，L1 自由度增大、残差变小，L2/L3 不需要太多码字也能覆盖残差，多数码字闲置
- **总体码本利用率从 ~64% 降到 22.7%**（696 / 3072 vs 2127 / 3072）

这是 distill30 的副作用。dev/mel 改善的同时码本利用率下降是有矛盾的——可能是少数高频码字与 decoder 形成了高效配合（"信息密度被重新分配到使用的少数码字"），但代价是：

- **鲁棒性差**：未来做信道扰动 / packet loss 时，少数高频码字一旦被打错，重建会崩
- **泛化风险**：当前 dev/mel 改善是在 train-clean 同源验证集上的，分布偏移下少数高频码字可能撑不住
- **L1 死码 82% 是结构性问题**：要解决需要专题修复（dead code reinit、k-means init、usage entropy regularization、按层 commitment 加权等），属于实验五消融或独立修复实验范畴

#### 4.5.3 评估指标范围

- 当前 PESQ-WB / STOI / SI-SNR / Mel L1 等只在 fixed (8 条 1 秒) 和 full_utterance (4 条长音频) 样本上算过
- 不代表完整验证集结果，更不代表通信信道下的最终质量
- 未运行 ASR，因此没有 WER/CER

### 10.8 关键发现

1. **同码率匹配下，500/1000/1500 bps 三档**，LCA 在 mel-L1、STOI、PESQ-WB 三项上一致优于 DAC 与 EnCodec，差值 95% CI 全部不含 0、Wilcoxon p < 0.001。两个 split 方向一致。
2. **跨码率 Opus 6 kbps**：mel-L1 维度 LCA L=3 大幅胜（test-clean -1.46，test-other -1.16），但 STOI / PESQ-WB 维度 Opus 6 kbps 略胜 LCA L=3（test-clean ΔSTOI -0.006、ΔPESQ -0.14；test-other ΔSTOI -0.029、ΔPESQ -0.19，全部 p<0.001）。这是 libopus 在 ≤8 kbps 下进入 SILK 模式、内部采样率降到 8 kHz、>4 kHz 高频被整体截断的指标系统性偏差。
3. **Opus 6/8 kbps mel-L1 异常高（中位数 ~2.20–2.27）但 STOI / PESQ 仍可接受**：原始 wav 与解码 wav 长度完全一致（diff = 0 samples），波形 RMS 0.029–0.034，SI-SNR 中位数 3.2 dB（6 kbps）/ 5.3 dB（8 kbps）。结合带宽截断，说明 mel-L1 在低码率 Opus 上不应作为单独判断指标，必须三指标联合判断。
4. **test-clean → test-other** 普遍劣化：SCIT-LCA L=3 mel-L1 从 0.8379 升到 1.1900，PESQ-WB 从 2.097 降到 1.756。所有 baseline 同向劣化，相对优势保持。
5. **8 样本快照→300 样本**：Opus 6 kbps mel-L1 从 8 样本快照的 ~0.86 跳到 300 样本的 ~2.30，对应"8 条 train-clean-100 都是短而简单 utterance"的取样偏差。这是 exp12 扩样本的最大 surprise。

### 11.1 exp5b（原 E3）：V0–V4 因子化 n=256 配对统计

- **代号**：exp5b（写在 exp5_lca_component_factorial 子目录下）
- **输出目录**：`output/experiments/exp5_lca_component_factorial_20260603_seed42/reports/statistical_tests_20260610/`
- **输入**：`eval_unified_n64_20260609/` 下 V0/V1/V2/V3/V4 的 n=256 per-sample CSV（每个 csv 240 行 = 8 样本 × 5 channel × 3 L × 2 model；本节按 (sample, L, channel) 计算 robust_imp）
- **方法**：每 (sample, L, channel) 计算 robust_imp = base_degradation − variant_degradation（越正越好），对 12 单元 × 256 样本 = 3072 个配对值做 paired t-test（缺 scipy fallback 到 statistics.NormalDist 正态近似）
- **关键结果**（mel-L1 鲁棒性改进，3072 配对）：

  | 比较 | 池化 Δ rob_imp | 95% CI | t | p (正态近似) | 12 单元中显著正向 |
  |---|---|---|---|---|---|
  | V3 − V1（在 random-L 上加 ChannelSim） | +0.00739 | [+0.00687, +0.00790] | 28.0 | <1e-300 | 12/12 |
  | V4 − V3（再加 consistency loss） | +0.00248 | [+0.00203, +0.00294] | 10.6 | <1e-300 | 10/12 |
  | V3 − V2（在 ChannelSim 上加 random-L） | +0.00236 | [+0.00188, +0.00284] | 9.6 | <1e-300 | 5/12 |
  | V2 − V1（ChannelSim-only vs random-L-only） | +0.00502 | [+0.00448, +0.00557] | 18.2 | <1e-300 | 12/12 |
  | V4 − V0（端到端总效益） | +0.00877 | [+0.00832, +0.00923] | 37.8 | <1e-300 | 12/12 |

- **解释**：V3−V1 路径（"random-L 上加 ChannelSim"）才是无 confound 的边际贡献，**+0.00739**；V4−V3 单独贡献 **+0.00248**（一致性损失）；V2−V1 因为同时改了 random-L 是否启用，不能解读为纯 ChannelSim 的边际贡献。这与 6 月 9 日修订稿 §6.3 的 V0–V4 解读一致，已经写进 `scit_speech_cn_revised_ml_20260610.md`。

## 14. 2026-06-13 exp15 codebook 利用率诊断（C-track，机制诊断，未替换主模型）

本节记录 exp15 的诊断阶段。**结论先行：原以为的"码本利用率不健康(17-27%)"在很大程度上是 32 样本统计偏差导致的夸大；真实情况是 L2/L3 利用率健康(>97%)，仅 L1 因语义聚焦呈结构性低利用率(~39%)。** 这是对论文局限性第 6 条的修正，对论文方向有利。诊断不替换主模型、不触发任何重跑（见下方"定位"）。

run_id：`exp15_codebook_health_20260611_seed42`

### 14.1 reinit-clobber 机制诊断（CPU）

- **发现**：`speechtokenizer/quantization/core_vq.py` 的 `EuclideanCodebook.forward` 训练分支里，dead-code reinit（`expire_codes_`）在第一行执行，但随后同一次 forward 用 `self.embed.data.copy_(embed_avg / cluster_size)` 重算整个码本，把刚 reinit 的码字**当场覆盖**——因此 dead-code reinit 实际是 **no-op**。
- **CPU 实测**（`commands/test_reinit_clobber.py`）：`||替换后-替换前||=108731`、`||覆盖后-替换后||=107644`，确认替换被同步抹掉。
- **出处确认（关键）**：该文件头 `# Copyright (c) Meta Platforms, Inc.`，是 Meta EnCodec 原版实现，SpeechTokenizer 沿用。比对 facebookresearch/encodec 原版 `core_vq.py`，`expire_codes_(x)` 同样在训练分支第一行、其后 EMA、最后 `embed ← embed_avg/cluster_size`，**逐行一致**，且原版有注释 `"We do the expiry of code at that point as buffers are in sync"`。**即：这是这一类 EMA-RVQ codec（EnCodec/DAC/SpeechTokenizer）共享的标准实现行为，不是本项目引入的 bug。** exp2 用此实现训练完全合规。
- **离线修复验证**（`commands/probe_reinit_fix.py`，合成 40 高斯簇 K=256 400step 3seed）：把 reinit 移到 EMA 重算之后 + 重置复活码字 EMA → 原版 dead_rate 96.5-97.3%/用码 7-9，修正版 dead_rate 0.0%/用码 84-90。证明修复机制有效（但合成数据，非真实 pipeline）。

### 14.2 真实模型 codebook 利用率基线（C1/Z，GPU 纯推理）

以 exp2 distill30 best ckpt（NAS 版主模型）为对象，复用 `scripts/codebook_usage_report.py` 统计**真实累积利用率**（非 EMA recent-window）：

| 层 | 32 样本（§4.5.2 旧）dead | 256 样本 used/dead | **1500 样本 used/dead** | 真实结论 |
|---|---|---|---|---|
| L1 | 82.5% | 392 / 61.7% | **399 / 61.0%** | 256→1500 仅 +7 码字 → **结构性封顶 ~39%** |
| L2 | 76.2% | 989 / 3.4% | **1012 / 1.2%** | 利用率 98.8%，**健康** |
| L3 | 73.3% | 986 / 3.7% | **998 / 2.5%** | 利用率 97.5%，**健康** |

- **核心修正**：§4.5.2 / 论文局限性第 6 条报的"L2/L3 死码 73-76%、总利用率 17-27%"是 **32 样本统计窗口太小**造成的假象。样本加到 1500，L2/L3 几乎满用（死码 1-3%）。
- **仅 L1 真塌缩**：1500 样本下 L1 仍只用 399/1024（~39%），且 256→1500 几乎不增长，证明是**结构性低利用率**（L1 承担帧级语义离散标签，码字需求本就少；distill 让 L1 聚焦窄语义子空间，进一步降低多样性）。与 exp16 的 L1 真实 entropy ~8 bit 吻合。
- **产物**：`c1_baseline_exp2/metrics/codebook_usage.csv`（256）、`c1z_baseline_exp2_full1500/metrics/codebook_usage.csv`（1500）。

### 14.3 定位与论文落点

- LCA 在 VCTK clean 条件下 STOI 全 L 一致小幅提升（与 LibriSpeech 一致）；L=3 mel-L1 改善（-0.059）；但 **L=1 mel-L1 明显变差（+0.246）**。这与 LibriSpeech clean 的"LCA 小幅改善"模式不同——VCTK L=1 上 LCA 反而劣化。
- 这是 clean 条件，LCA 的设计目标是扰动鲁棒性（exp8/9），clean 上的 L=1 劣化属可接受代价范畴，但应诚实记录："LCA 的 clean 收益不跨语料稳定，VCTK L=1 上反而劣化"。

### 15.5 诚实 caveats

- VCTK 48kHz→16kHz 重采样损失 >8kHz 高频，PESQ/STOI 绝对值受影响；但 Base/LCA/LibriSpeech 同处理，相对对比有效。
- 300 子集（非全量 44455 条 mic1），跨 110 说话人均匀采样；结论为子集级。
- **仅客观指标，无 VCTK ASR/WER**（VCTK 有 transcript 但未做对齐评估）。
- **AISHELL 中文未做**（中文 ASR 需 multilingual/large Whisper，留 future work 或第二阶段）。
- LCA 在 VCTK L=1 clean 上劣化是真实现象，不藏。

### 15.8 AISHELL-1 中文 ASR/CER（whisper medium，完成）

- **方法**：multilingual Whisper `medium`（762M）+ `language="zh"`，字符级 CER（中文不分词，去空格按字符算），对比 ground-truth transcript（cer_vs_gt）与原始音频 whisper 转写（cer_vs_original_whisper，隔离 codec 退化）。脚本 `commands/evaluate_asr_cer_zh.py`。
- **完整性**：CSV 1800 行，0 skip（全 transcript 匹配），耗时 ~60min（2100 次中文转写）。

**中文 CER（vs ground-truth）：**

| L | Base CER | LCA CER | ΔCER (LCA-Base) |
|---|---:|---:|---:|
| 1 | 1.508 | 1.556 | +0.049 |
| 2 | 0.843 | 0.749 | **-0.094** |
| 3 | 0.540 | 0.498 | **-0.042** |

**核心结论（诚实，符合"英文模型中文 zero-shot"预期）**：
1. **L=1（500bps）中文几乎不可懂**：CER 1.5（>1.0 因插入错误），whisper 几乎无法识别 500bps 重建的中文。极低码率 + 跨语言双重压力下的真实失败。

## 16. 2026-06-13 exp5c LCA consistency loss 训练动力学诊断（纯后处理，完成）

验证修订稿 §3.3 末段关于 LCA v2 consistency loss "避免扰动下复制偏差"机制的声明——从训练曲线层面看：带 consistency 的 V4 是否使"扰动解码偏离 clean 解码"的幅度（gap）小于不带 consistency 的 V3，且不损害 clean 重建质量。

run_id：`exp5c_consistency_dynamics_20260611_seed42`。**纯后处理**：读 V0–V4 的 TensorBoard event（流式解析，不重训、不占 GPU）。

### 16.1 方法与数据

- **TB 曲线提取**（`commands/extract_dynamics_curves.py`，流式 EventFileLoader 避免 EventAccumulator OOM；V4 合并 exp3-v2 的两个 event 文件即中断前+续训后）：
  - V0–V3：`exp5_lca_component_factorial_20260603_seed42/runs/V{0..3}_*/checkpoints/logs`
  - V4：`exp3_low_load_channel_aware_adaptation_v2_strong_perturb_20260531_seed42/checkpoints/logs`
- **consistency 激活确认**：仅 V4 有 `train/lambda_consistency_used`=0.5、`train/loss_consistency`>0；V0–V3 全为 0（variant_summary.csv 证实）。
- **gap 定义**：`gap = dev/comm_mel[L,channel] - dev/comm_mel[L,clean]`，即"扰动重建比 clean 重建差多少"。gap 越小 = 扰动解码越接近 clean 解码 = consistency 机制目标。
- 产物：`metrics/{dynamics_long.csv(9724行), robustness_gap_dynamics.csv(364行), variant_summary.csv}`。

### 16.2 核心结果：V4 vs V3 扰动 gap（final-window 末3个dev点均值）

| L | channel | V3 gap | V4 gap | V4−V3 |
|---|---|---:|---:|---:|
| 1 | dropout-mid | 0.0118 | 0.0119 | +0.0001 |
| 1 | dropout-high | 0.0246 | 0.0227 | -0.0019 |
| 1 | substitution-mid | 0.0893 | 0.0356 | **-0.0537** |
| 1 | substitution-high | 0.2192 | 0.1186 | **-0.1006** |
| 2 | substitution-mid | 0.0575 | 0.0336 | -0.0238 |
| 2 | substitution-high | 0.1861 | 0.1191 | **-0.0670** |
| 3 | substitution-mid | 0.0547 | 0.0307 | -0.0241 |
| 3 | substitution-high | 0.1792 | 0.0942 | **-0.0850** |
| (dropout-mid/high L2/L3) | — | — | — | ±0.001 |

**V4 在 11/12 单元上 gap 更小，平均 −0.0299。**

### 16.3 关键发现（差异化模式印证机制）

- **consistency 效果高度集中在 substitution 扰动**：sub-high 上 gap 缩小 0.067–0.101（L1/L2/L3），sub-mid 缩小 0.024–0.054；而 **dropout 扰动上几乎无差异（±0.002）**。
- **机制解释**：consistency loss 惩罚 clean 解码与扰动解码的 mel 偏离。substitution（随机替换 RVQ 索引）正是制造"错误内容/复制偏差"的扰动，consistency 把扰动解码拉回 clean，故 sub 上 gap 大幅缩小；dropout（previous-index 替换）本就接近 clean，可压缩空间小。这一**差异化模式**正面支持 §3.3 "避免扰动下复制偏差"的因果声明——不是全局平移，而是专门压制 substitution 类偏差。
- **clean 质量守门通过**：V4 `dev/full_depth_mel_error` best=0.9811 vs V3 best=0.9792（+0.0019，可忽略）——consistency 未牺牲 clean 全深度重建。

### 16.4 诚实边界（重要）

- **run-level confound**：V0–V3 是 exp5 因子化同一 run，**V4 是 exp3-v2 的另一个 run**（中断+续训、cosine 调度等可能不同）。因此 V4 vs V3 的曲线对比是**动力学层面的佐证，不是同 run 受控 ablation**。受控的 V3−V1 / V4−V3 因子化贡献（n=256 配对统计）见 §11.1 exp5b——那才是论文主证据，本节为动力学补充。
- `dev/comm_mel/L*_clean` 上 V4 也低于 V3（L1 −0.17/L2 −0.05/L3 −0.02），但这受 run-level confound 影响（V4 不同 run），**不可单独归因于 consistency**；clean 守门以同口径的 `full_depth_mel_error` best 近似持平为准。
- gap 用 final-window 末3点均值，dev/comm_mel 本身有方差；结论方向稳健（11/12）但具体数值非精确。

### 16.5 论文落点

- 支撑修订稿 §3.3 consistency 机制段：可加"训练动力学上，加入 consistency loss 后 substitution 扰动下的 comm_mel 偏离（gap）相比无 consistency 变体缩小约 0.07–0.10（sub-high，11/12 (L,channel) 单元方向一致），且不损害 clean full-depth 重建；dropout 扰动上无显著差异，与 consistency 专门压制替换型复制偏差的机制一致"。
- 与 §11.1 exp5b（受控 n=256 因子化）互补：exp5b 给受控因果贡献，exp5c 给动力学机制图像。
- **诚实标注 run-level confound**，不把 V4-vs-V3 写成受控 ablation。
- **尚未回写**（按约定论文回写由用户决定）。

补论文长期缺口（原 §7-2「AMR-WB 与 Codec2 缺失」）。两者编码器都不在 conda-forge ffmpeg 6.1.2 里，故**单独下了 gyan.dev ffmpeg 8.1.1 完整构建**（`tools/ffmpeg-8.1.1-full_build/`，含 `--enable-libvo-amrwbenc` + `--enable-libcodec2`），**不动 conda 的 6.1.2**（exp4/exp12 其余 baseline 仍可复现）。

### 19.2 核心结果（配对 Wilcoxon，SCIT-LCA vs 区间内 Codec2，同样本）
| 比较 | Δmel-L1 | ΔSTOI | ΔPESQ-WB |

### 20.3 核心结论（ΔViSQOL = LCA − baseline）
