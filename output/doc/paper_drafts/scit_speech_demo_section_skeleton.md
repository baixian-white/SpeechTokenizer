# §X 三用户中心路由实时通信原型（论文小节草稿 — 已填实测数字）

> 用途：把论文 §7 第 7 条"多用户实时验证仍留作未来工作"升级为"已有实时原型 + 定量测量"。
> 表 X 数字来自 `run_benchmark.py` 在 RTX 5070 Ti（`speechtokenizer` 环境）上 GPU+CPU × L∈{1,2,3} × 60 s 的实测（`benchmark_results.csv`）。并入主稿位置由用户决定。

## 系统结构

我们实现了一个三用户中心路由实时语音通信原型，验证共享码本索引传输接口（§3.1）在端到端多用户实时链路下的可行性。原型加载的模型权重 sha256 = `af60223b2f44733f5a43d5a022871dad061dfe2421473c96f5d350c3d4b49a5a`，与 §4.2 / 附录 A 的 SCIT-Speech-LCA v2 逐位一致（同一 NAS 编码器 + 同一接口参数 16 kHz / 总下采样 320 / `f_q`=50 / `n_q`=3 / `K`=1024），即本原型与论文评估用的是同一个模型，无重训、无改动。系统由一个中心路由（Router）与三个对等客户端（A/B/C）组成：

- **客户端**：采集 → SCIT-Speech 编码器编码 → 截断到前 `L` 层 RVQ 索引 → 按 `⌈log₂K⌉=10` bit/索引位打包成紧凑字节流 → 通过 TCP 发往 Router；接收侧反向解包 → 解码 → 抖动缓冲 → 多路混音播放。每客户端复用同一套预共享码本与解码器（§3.1）。
- **Router**：只按房间转发索引 packet，**不解码、不混音、不接触码本**——这与 §3.1"码本与解码器为收发端预共享系统知识、信道仅承载离散索引"的接口契约直接对应。Router 侧据此可直接核算多用户聚合信道占用。

> 注：索引在传输前以占位性逐包密文转发（按比特异或）做链路演示，**不对加密强度作任何宣称**；严格信道安全（如密钥流推进、消息认证）不在本原型范围。

## 测量协议

为可复现，A/B/C 三端均灌入同一段固定语音（循环播放）而非实时麦克风，互发并在接收端无头解码（不开扬声器，解码计算照常发生）。每个工作点 `L ∈ {1, 2, 3}` 与每种设备（GPU=RTX 5070 Ti / CPU）各跑一轮 60 秒，采集端到端编码/解码实时率（RTF）、抖动缓冲占用、每端聚合带宽与丢包率。编码分块 chunk = 0.5 s（须取下采样率 320 的整数帧：0.5 s@16 kHz=8000 样点=25 帧；分块重建与整句重建的 mel-L1 差 ≤ 0.016，即实时模式质量与 §5 离线整句一致，详见对齐说明）。

## 结果

测量在单机回环(RTX 5070 Ti,`speechtokenizer` 环境)上完成,A/B/C 三端全互联(每端 1 路发送 + 2 路接收),每组合采集 60 s,三端取均值。

关键观察:
- **GPU 与 CPU 下全链路实时性均成立**:三用户并发(每端同时编码 1 路、解码 2 路)下,GPU 的 encode/decode RTF 均值 0.04–0.05、p95 ≤0.046;CPU 的 encode/decode RTF 均值 0.17–0.22、p95 ≤0.36——**均远小于 1**,即单机即可实时承载三用户并发,无需 GPU。全 6 组合 60 s 采集下 **drop_rate 全为 0**。
- **单流码率与 §3.1 名义 `500 L` 一致**:每个 0.5 s 分块封装 `ceil(L·25·10/8)` 字节(L=1/2/3 = 32/63/94 字节,等效 512/1008/1504 bps),实测单流发送吞吐 484/956/1435 bps(略低于名义,系有限窗口内发送节奏所致),与 §3.1 名义核算在取整误差内一致。
- **每端聚合带宽随接收流数线性增长**:每端 body = 1 路发送 + 2 路接收 ≈ 3×`500 L`(L=1/2/3 实测 1.44/2.85/4.26 kbps);total 含 TCP/JSON 头开销(11.5–14.4 kbps),与 §3.1 "payload 上界 + 协议栈开销" 的区分一致。
- **单向延迟预算 750 ms**(0.5 s 分块 + 0.25 s 抖动缓冲目标),高于实时语音舒适区,原型未做延迟优化(见边界 3)。

## 边界（必写，审稿人会盯）

1. **实时分块与离线整句质量一致（已验证）**：本原型按 0.5 s 逐块编解码；在固定样本上分块重建相对整句重建的 mel-L1 差 ≤ 0.016（L=1/2/3 分别 +0.016/+0.005/+0.0002），即实时模式与 §5 离线整句**质量等价**。注意 chunk 须取下采样率 320 的整数帧——0.25 s（12.5 帧，非整数）会触发严重边界退化（mel-L1 +1.5），故不可用；0.5 s 起质量即收敛。本节客观指标仍以系统性能（RTF/延迟/带宽）为主，重建质量绝对值以 §5 为准。
2. **TCP / 局域网，不演示丢包鲁棒性**：本原型用 TCP（有重传），不复现信道丢包；丢包/突发鲁棒性见 §5.4 的离线索引层评估。弱网实时（UDP/RTP）留作未来工作。
3. **延迟未优化**：0.5 s 分块 + 0.25 s 抖动缓冲目标 ≈ 单向 750 ms，高于实时语音舒适区（ITU-T G.114 单向 <150 ms）；本原型未做延迟优化（更小分块受下采样整除约束——0.25 s=12.5 帧非整数会致质量塌方，需 codec 改造为流式因果结构，留作未来工作）。
4. **占位密文转发**：逐包异或仅作链路演示，不等价于任何安全保证。
