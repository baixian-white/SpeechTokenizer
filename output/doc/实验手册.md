# SCIT-Speech 极低码率语音通信实验手册

本文档用于固定论文实验路线。它不是论文正文，而是后续训练、评估、结果记录和论文写作的执行手册。

## 1. 实验总目标

本文研究对象不是某个具体开源 tokenizer，也不写成抽象的“方法学框架”，而是一个明确的低码率语音通信方法：**SCIT-Speech，一种基于共享 RVQ 码本索引传输的极低码率语音通信方法**。发送端与接收端预先共享 RVQ 码本、模型参数和系统配置；通信过程中，信道仅承载离散码本索引序列。

```text
输入语音 x(t)
-> 发送端表示编码器 E_theta
-> 连续语音表示 Z
-> 固定共享 RVQ 码本 C*
-> 离散索引矩阵 I
-> 保留前 L 层索引 I_L
-> 索引级低负载传输
-> 接收端码本查找与语音重建
-> 重建语音 x_hat(t)
```

实验要回答的主问题是：

> 当发送端和接收端预先共享 RVQ 码本、模型参数和系统配置后，是否可以在运行时只传输紧凑的离散索引序列，并在约 500、1000 和 1500 bps 三个工作点上保持可用的语音可懂度和基本重建质量？

实验路线分为八组，其中实验一到实验五构成当前主论文的核心证据；实验六到实验八用于把论文从“小样本系统验证”推进到更扎实的低码率语音通信方法验证：

1. **实验一：NAS 轻量化语义提取架构搜索**。搜索 `Z` 之前的发送端语义提取架构，在保持低负载索引接口不变的前提下降低计算量和延迟。
2. **实验二：模型训练**。基于选定架构训练一个属于本文实验体系的共享码本索引语音模型，作为 SCIT-Speech 的系统实例。
3. **实验三：低负载/轻量信道感知适配**。让模型适应只传输前 `L` 层索引以及轻量索引扰动的通信条件。
4. **实验四：baseline 对比**。与传统语音编码、神经音频编码和直接索引传输替代方案进行负载-可用性对比。
5. **实验五：消融与诊断**。验证 NAS 轻量化、低负载训练、语义引导、轻量信道扰动等设计是否必要。
6. **实验六：扩展测试集与跨语料验证**。在更大的测试集合和至少一个跨语料集合上验证结论是否稳定。
7. **实验七：更通信化的索引/包级扰动验证**。补充 burst loss、packet loss 或 Gilbert-Elliott 信道，验证 index-only payload 在非独立错误下的可用性边界。
8. **实验八：系统可行性与主观验证**。三用户实时 demo、payload/latency 统计和轻量主观听感作为补充材料；若时间不足，三用户 demo 可降级为附录或删除，不作为主结论证据。

## 2. 命名与论文叙事原则

论文正文中不以具体开源项目名作为方法主语。统一使用以下中性术语：

- `speech representation encoder`
- `shared RVQ codebooks`
- `discrete codebook indices`
- `index-only transmission`
- `receiver-side codebook lookup`
- `speech reconstruction decoder`

本文内部暂定模型名：

```text
SCIT-Speech
```

含义：

```text
Shared-Codebook Index Transmission Speech Model
```

不要在模型名里标注层数。层数是实验配置，不是方法名。

不推荐在方法图、标题、Abstract 和贡献表述中出现具体开源 tokenizer 名称。如果实现参考了已有 RVQ speech tokenizer 的公开结构或训练思想，应在 Related Work 或 Implementation Details 中诚实引用，但不能把本文贡献写成该项目本身。

本文贡献应落在：

- 共享码本索引传输方法；
- 运行时信道中只传输离散 RVQ 索引的通信机制；
- 传输负载建模；
- 低负载与轻量信道感知训练或适配；
- 传输层数、传输负载和语音可用性之间的实验权衡。

## 3. 公共实验设置

### 3.1 主配置

第一版主实验使用以下配置：

```text
model_name = SCIT-Speech
M = 3
K = 1024
sample_rate = 16000
encoder_downsample_rate = 8 * 5 * 4 * 2 = 320
latent_rate = 16000 / 320 = 50 steps/s
```

其中 `M` 是训练得到的最大 RVQ 层数，`K` 是每层码本大小。本文不把 `M = 3` 写成普遍结论，而是作为本文系统实例的设计容量。实际通信时传输层数由 `L` 控制：

```text
C* = {C_1*, C_2*, C_3*}
I = {i_{m,t}} in {1, ..., K}^{3 x T_q}
I_L = I_{1:L, :},    L in {1, 2, 3}
```

理想定长索引负载为：

```text
R_index(L) = L * latent_rate * ceil(log2 K)
           = L * 50 * 10
           = 500L bps
```

| Transmitted layers L | Ideal raw index load |
|---:|---:|
| 1 | 500 bps |
| 2 | 1000 bps |
| 3 | 1500 bps |

注意：这是 bit-packed ideal index load，不等于程序中用 `int64` 数组、JSON header 或 TCP 包传输时的实际 payload。论文主表应同时报告 ideal index bitrate 和实际 packetized payload。

### 3.2 数据集

训练数据建议：

- 第一版使用 LibriSpeech train-clean-100；
- 所有音频统一为 16 kHz、单声道；
- 固定训练、验证、测试划分；
- 每条样本记录 speaker id、utterance id、时长和原始文本转写。

测试数据建议：

- LibriSpeech test-clean；
- LibriSpeech test-other；
- 可选加入少量真实通信语音或三用户 demo 录音作为系统补充材料。

### 3.3 公共评价指标

| Dimension | Metrics |
|---|---|
| Transmission load | ideal index bitrate, packetized payload, compression ratio |
| Intelligibility | ASR-WER/CER, STOI |
| Naturalness | PESQ, ViSQOL, optional MOS |
| Semantic adequacy | transcript similarity, embedding similarity, optional BERTScore |
| Speaker preservation | speaker embedding cosine, optional |
| Mild robustness | degradation under light index dropout/substitution |
| System usability | RTF, end-to-end latency, packet payload |

评价模型与训练阶段教师模型需要区分。ASR、speaker embedding 和用于最终语义相似度评价的模型只用于评价，不能参与模型训练；语义教师模型可以作为训练辅助信号使用，但必须固定、不可随本文模型共同训练，并且不作为论文贡献。

## 4. 实验一：NAS 轻量化语义提取架构搜索

### 4.1 实验目的

实验一用于搜索发送端 `Z` 之前的轻量化语义提取架构。这里的搜索对象是 `E_theta` 中从输入语音到连续表示 `Z` 的前端网络，也就是：

```text
x(t) -> semantic/acoustic encoder front-end -> Z
```

该实验的目标不是搜索 RVQ 码本、传输层数或接收端通信机制，而是在保持后续共享码本索引接口不变的前提下，寻找更轻量、更低延迟、但仍能保留语音内容信息的 encoder 架构。

实验一要回答：

- 是否可以用 NAS 得到一个比手工设计 encoder 更轻量的语义提取架构；
- 该架构是否仍能产生适合 RVQ 量化的连续表示 `Z`；
- 轻量化是否降低参数量、MACs、RTF 或端到端延迟；
- 轻量化是否明显损害后续 `L = 1, 2, 3` 索引传输下的可懂度和语义保持。

### 4.2 搜索边界

NAS 只搜索 latent 之前的语义提取/下采样部分。固定不搜索：

- RVQ 码本层数 `M`；
- 每层码本大小 `K`；
- 索引传输方式；
- `L = 1, 2, 3` 的负载控制策略；
- ChannelSim；
- 三用户通信协议。

为了保证搜索出的 encoder 可以无缝接入后续共享码本量化，以下接口必须固定：

```text
sample_rate = 16000
encoder_downsample_rate = 320
latent_rate = 50 steps/s
latent_dimension = d (current default: 1024)
Z shape = R^{d x T_q}
```

也就是说，NAS 可以改变 `Z` 之前如何提取语义/声学表示，但不能改变 `Z` 作为后续 RVQ 输入的形状和时间率。

### 4.3 搜索空间

建议搜索空间围绕轻量化卷积语音 encoder 设计：

| Component | Candidate choices |
|---|---|
| residual block operator | standard conv, depthwise-separable conv, dilated conv |
| kernel size | 3, 5, 7, 9 |
| channel width | small / medium / base width |
| squeeze-excitation | on / off |
| activation | ELU, Snake, GELU optional |
| temporal modeling | no LSTM, 1-layer LSTM, 2-layer LSTM |
| block depth | per-stage residual block count |

第一版搜索应保持 stride schedule 不变：

```text
strides = [8, 5, 4, 2]
```

原因是 stride schedule 决定 latent rate，也直接决定索引负载。如果 NAS 同时搜索 stride，会把“架构轻量化”和“通信负载变化”混在一起，不利于论文解释。

### 4.4 搜索目标

NAS 的目标是多目标权衡，而不是只追求最低 loss。推荐综合考虑：

```text
score(a) =
  L_sem(a)
+ mu * L_proxy_rec(a)
+ lambda_macs * log(MACs(a) / MACs_base)
+ lambda_params * log(Params(a) / Params_base)
+ lambda_rtf * RTF(a)
```

其中 `a` 表示候选架构：

- `L_sem(a)`：候选 encoder 输出与语义教师表示之间的距离，用于衡量语义提取能力；若二者维度不同，应使用固定投影或轻量对齐头计算 proxy loss，不改变最终通信接口；
- `L_proxy_rec(a)`：短训阶段的重建或 mel proxy loss，用于防止只优化语义而损害可听重建；
- `MACs(a)` 和 `Params(a)`：计算量和参数量；
- `RTF(a)`：真实推理速度指标。

论文中可以把最终选择描述为 Pareto selection：

> We select the encoder architecture from the Pareto frontier of semantic preservation and computational cost.

### 4.5 搜索流程

推荐执行流程：

```text
1. 构建 NAS 搜索子集
2. 定义候选 encoder 搜索空间
3. 对每个候选架构进行短训或 proxy evaluation
4. 记录 semantic loss、proxy reconstruction loss、参数量、MACs 和 RTF
5. 形成 Pareto frontier
6. 选择一个轻量化且语义保持较好的架构
7. 将该架构作为后续 SCIT-Speech-Base 的 encoder
8. 在实验二中进行完整模型训练
```

搜索阶段可以使用较小训练子集和较短训练轮数，目的是筛选架构，不是得到最终模型。最终论文结果必须基于选定架构重新训练的完整模型，而不是直接使用 NAS 短训权重。

### 4.6 NAS 对照条件

至少比较：

```text
Hand-designed encoder
NAS-searched lightweight encoder
```

推荐报告：

| Encoder | Params | MACs | RTF | Semantic loss | Proxy rec loss |
|---|---:|---:|---:|---:|---:|

如果资源允许，可以额外报告选定 NAS encoder 接入完整模型后的表现：

| Encoder | L | WER | STOI | PESQ/ViSQOL | Semantic sim | RTF |
|---|---:|---:|---:|---:|---:|---:|

### 4.8 实验一成功标准

最低成功标准：

- 搜索出的架构满足固定输出接口，即 downsample rate 和 latent dimension 不变；
- 参数量、MACs 或 RTF 至少一项优于 hand-designed encoder；
- 语义 proxy 指标没有明显劣化；
- 接入完整 SCIT-Speech 训练流程后可以正常训练和解码；
- 不改变后续 `M = 3`、`K = 1024`、`L = 1, 2, 3` 的通信负载分析。

如果 NAS 架构明显更轻但语音可懂度显著下降，则不应作为主模型，只能作为轻量化探索的负例。

### 4.9 实现口径注意

当前工程实现中如果 NAS 脚本同时替换 encoder 和 decoder，需要在论文实验口径中拆开说明。本文 NAS 实验的主张只针对发送端 `Z` 之前的语义提取 encoder：

```text
x(t) -> encoder -> Z
```

如果为了工程兼容或重建质量，在完整训练中使用了与 NAS encoder 对称的 decoder 结构，应将其写成 implementation variant 或消融条件，而不能把 decoder 侧变化也计入“语义提取 NAS”的贡献。主实验推荐保持 decoder 结构尽量一致，只比较：

```text
hand-designed encoder + fixed decoder
NAS-searched encoder + same/fixed decoder
```

若必须同时替换 decoder，则需要额外报告：

```text
NAS encoder only
NAS encoder + NAS-mirrored decoder
```

以避免审稿人质疑性能提升来自 decoder 容量变化，而不是来自发送端语义提取架构搜索。

## 5. 实验二：SCIT-Speech 模型训练

### 5.1 实验目的

实验二的目标是基于实验一选定的 encoder 架构，训练一个属于本文实验体系的共享码本索引语音模型，而不是直接把已有公开 checkpoint 当作本文方法。该模型需要具备三种能力：

1. 将语音编码为连续表示 `Z`。
2. 使用共享码本 `C*` 将 `Z` 量化为离散索引 `I`。
3. 在接收端根据索引和共享码本恢复语音。

实验二的产物是可用于后续通信实验的基础模型 checkpoint。它本身不是论文最终结论，而是实验三、实验四和系统验证的前置条件。

### 5.2 第一层偏语义的理由

实验二保留一个通信导向的层级设计意图：尽量使较低层索引，尤其是第一层索引，优先保留语音内容和可懂性相关信息。

理由是：在低负载通信中，`L = 1` 是最极端的低负载操作点。如果第一层索引主要承载语音内容和可懂性，系统即使只传输 `500 bps` 左右的索引流，也仍有机会恢复主要语音内容；当链路预算允许 `L = 2` 或 `L = 3` 时，后续层再补充自然度、音色、韵律和细节。

这不是要证明“第一层天然等价于语义 token”，也不是把本文写成 tokenizer 分层解释论文。第一层偏语义只是服务于低负载通信的工程设计：最低负载操作点应优先保留对通信可用性最关键的信息。

### 5.3 需要训练的组件

实验二训练：

- 发送端表示编码器 `E_theta`；
- 共享 RVQ 码本 `C*`；
- 语音重建解码器 `D_psi`；
- 训练阶段使用的判别器或感知损失模块。

实验二不训练：

- 通信信道；
- bit packing / packetization；
- 加密模块；
- 网络通信与三用户路由模块；
- ASR 评价模型；
- baseline speech codec。

### 5.4 基础训练目标

基础训练使用 full-depth 重建：

```text
x -> E_theta -> Z -> C* -> I
use I_{1:3, :} to reconstruct x_hat_3
```

推荐训练目标：

```text
L_base =
  lambda_rec * waveform reconstruction loss
+ lambda_mel * multi-scale mel loss
+ lambda_commit * RVQ commitment loss
+ lambda_sem * semantic distillation loss
+ lambda_adv * adversarial loss
+ lambda_fm * discriminator feature matching loss
```

其中：

- waveform reconstruction loss 和 multi-scale mel loss 保证基础可听质量；
- RVQ commitment loss 稳定离散码本学习；
- semantic distillation loss 用于引导较低层索引保留内容信息；
- adversarial loss 和 feature matching loss 只用于提升训练阶段的感知质量，不属于通信传输对象。

语义蒸馏的论文表述应保持克制：它是训练辅助信号，用于使低负载索引更有机会保留可懂内容，不是本文宣称提出的新语义 tokenizer。

### 5.5 两条训练路线

手册保留两条路线，方便根据真实训练结果选择论文主线。

**路线 A：一步式低负载/轻量信道感知训练。**

```text
train SCIT-Speech directly with random L and mild ChannelSim from the beginning
```

优点：

- 论文叙事上更像端到端通信模型；
- 不需要把低负载能力解释成后补微调；
- 如果训练稳定，结果可能更简洁。

**路线 B：两阶段路线，推荐作为主执行路线。**

```text
Stage B1: train SCIT-Speech-Base with full-depth reconstruction
Stage B2: fine-tune/adapt it with low-load and mild channel-aware objectives
```

优点：

- 训练更稳；
- 实验二和实验三边界清楚；
- 便于用 `SCIT-Speech-Base` vs. `SCIT-Speech-LCA` 做消融；
- 与当前讨论中的“先训练模型，再做低负载感知微调”一致。

第一版建议优先执行路线 B。路线 A 可以作为补充实验或未来版本路线，不应在当前论文中强行承诺。

### 5.7 码本使用情况 sanity check

实验二需要额外检查 RVQ 码本是否被有效使用，避免后续 `L = 1, 2, 3` 分析建立在码本 collapse 的模型上。该检查不作为独立大实验，而是实验二的训练质量诊断。

建议统计：

| Metric | Meaning |
|---|---|
| codebook usage rate | 每层码本中被实际使用过的 codeword 比例 |
| codebook perplexity | 索引分布的有效复杂度，用于观察是否过度集中 |
| dead code ratio | 长时间未被选中的 codeword 比例 |
| layer-wise index distribution | 每层索引分布直方图 |
| layer-wise commitment loss | 每层量化稳定性诊断 |

最低要求：

- 每一层 RVQ 码本都应有非平凡使用率；
- 第一层不应只集中在极少数 codeword 上；
- 后续层可以更稀疏，但不应大面积完全失活；
- 若某层 dead code ratio 过高，需要记录并解释，必要时调整训练超参数或码本更新策略。

推荐将结果保存为：

```text
output/experiments/exp2_scit_speech_training/reports/codebook_usage.md
output/experiments/exp2_scit_speech_training/reports/codebook_usage.csv
```

论文中可以简要报告该诊断，用于说明训练得到的共享码本是可用的，而不是只依赖少数离散符号。

### 5.8 实验二成功标准

最低成功标准：

- checkpoint 可正常加载；
- 模型参数与实验设定一致，即 `M = 3`、`K = 1024`、16 kHz、downsample rate 320；
- full-depth 即 `L = 3` 重建语音可听且没有明显异常；
- `L = 1, 2, 3` 均可成功解码，不出现崩溃、长度错位或大面积静音；
- 从 `L = 1` 到 `L = 3`，重建质量应呈现基本改善趋势。
- 码本使用情况没有明显 collapse。

如果 `L = 1` 声音自然度较差但 ASR 仍能识别主要内容，可以保留，因为这正是极低负载语义通信的一个操作点。

## 6. 实验三：低负载/轻量信道感知适配

### 6.1 实验目的

实验三的目标是验证：在共享码本模型已经具备基本重建能力之后，面向通信场景的训练目标是否可以提升低负载索引传输下的可用性。

实验三重点验证：

- 只传输前 `L` 层索引时，模型是否仍可恢复可懂语音；
- `L = 1, 2, 3` 之间是否形成清晰的负载-可用性曲线；
- 低负载感知训练是否提升 `L = 1` 和 `L = 2` 下的语音可用性；
- 轻量索引扰动训练是否降低小规模索引错误带来的质量退化。

实验三产物命名：

```text
SCIT-Speech-LCA
```

其中 `LCA` 表示 low-load- and channel-aware。它是实验标签，不建议在论文方法标题中过度突出。

### 6.2 微调策略

默认策略：**end-to-end fine-tuning**。

```text
initialize from SCIT-Speech-Base
fine-tune encoder, RVQ codebooks, and decoder together
```

理由：

- 我们希望模型整体适应低负载通信目标；
- 冻结操作会限制上限；
- 当前主问题不是分析 decoder 单独补偿能力，而是得到更适合低负载通信的模型。

`decoder-only fine-tuning` 可作为诊断消融，但不作为主实验路线。若使用，需要明确说明它只是为了验证“接收端重建模块是否能单独适应截层输入”，不是最终推荐模型。

### 6.3 训练流程

```text
for each batch:
    encode x -> Z
    quantize Z -> I
    sample L from {1, 2, 3}
    retain I_L = I_{1:L, :}
    sample mild channel condition c
    perturb I_L -> I_tilde_L using ChannelSim(I_L; c)
    reconstruct x_hat_{L,c} from I_tilde_L and C*
    optimize low-load- and channel-aware objective
```

训练目标：

```text
L_total =
  alpha * L_full(x, x_hat_3)
+ beta  * E_{L in {1,2,3}, c in C_mild} L_comm(x, x_hat_{L,c})
+ lambda_commit * RVQ commitment loss
+ lambda_sem * semantic distillation loss
+ lambda_adv * adversarial loss
+ lambda_fm * discriminator feature matching loss
```

其中：

- `L_full` 用于保持 full-depth 重建上限，避免低负载微调导致整体音质崩坏；
- `L_comm` 用于优化低负载和轻量扰动条件下的通信可用性；
- `lambda_sem` 继续约束较低层索引对内容信息的保留；
- `c` 是轻量信道条件，不是复杂物理信道建模。

### 6.4 轻量 ChannelSim 设计

第一版只做 index-level mild perturbation，不单独声称强信道鲁棒。

这里的 `clean`、`index dropout` 和 `light index substitution` 都作用在离散索引矩阵 `I_L` 上，而不是作用在语音波形上。它们用于模拟索引级传输过程中可能出现的轻量状态：

```text
clean = 索引无损到达
index dropout = 少量索引没有收到
light index substitution = 少量索引被错误解成另一个合法码本地址
```

**clean** 表示理想索引传输条件。发送端保留的索引矩阵与接收端获得的索引矩阵一致：

```text
I_tilde_L = I_L
```

该条件用于评估模型在无信道损伤时的低负载重建能力。

**index dropout** 表示少量索引缺失。它模拟传输过程中部分索引位置没有成功到达接收端，例如：

```text
original:  [12, 57, 88, 31, 102]
dropout:   [12, 57, ?,  31, 102]
```

由于当前解码路径通常只能接收合法整数索引，第一版不建议直接引入未知 token。推荐使用 `previous-index replacement` 作为实现方式，即用前一个时间步的合法索引替代缺失位置：

```text
replaced:  [12, 57, 57, 31, 102]
```

该条件用于模拟轻微丢包或索引缺失对接收端重建的影响。

**light index substitution** 表示少量索引被错误替换为另一个合法码本地址。它模拟索引比特错误或解映射错误，例如：

```text
original:      [12, 57, 88,  31, 102]
substitution:  [12, 57, 401, 31, 102]
```

其中 `88` 被错误接收为 `401`。由于 `401` 仍是合法索引，接收端可以正常查码本，但查到的是错误 codeword。该条件用于模拟轻量索引误码对重建语音可用性的影响。

| Perturbation | Meaning | Suggested range |
|---|---|---|
| clean | 无扰动，理想索引传输 | always included |
| index dropout | 随机擦除少量索引 | `p_drop = 0.01, 0.03, 0.05` |
| light index substitution | 少量索引被替换为其他码本地址 | `p_sub = 0.001, 0.005, 0.01` |
| short burst erasure | 连续 1-3 个 latent frames 被擦除 | optional |

实现建议：

- 如果当前 decode path 只能接收合法整数索引，优先使用 `light index substitution` 或 `previous-index replacement`；
- `mask token` 或 `zero-vector erasure` 需要改量化/解码路径，第一版不强行引入；
- 论文中可以把扰动抽象为 `ChannelSim(I_L; c)`，实现细节放到实验设置。

### 6.5 实验三评价

模型条件：

```text
SCIT-Speech-Base
SCIT-Speech-LCA
```

Layer sweep：

```text
L in {1, 2, 3}
```

信道条件：

| Condition | Setting |
|---|---|
| clean | `p_drop = 0`, `p_sub = 0` |
| dropout-low | `p_drop = 0.01`, `p_sub = 0` |
| dropout-mid | `p_drop = 0.03`, `p_sub = 0` |
| substitution-low | `p_drop = 0`, `p_sub = 0.001` |
| substitution-mid | `p_drop = 0`, `p_sub = 0.005` |

主要表格建议：

| Model | L | Load | Channel | WER | STOI | PESQ/ViSQOL | Semantic sim | RTF |
|---|---:|---:|---|---:|---:|---:|---:|---:|

预期结论形式：

- `L = 1` 提供最低负载和基本内容保留，但自然度有限；
- `L = 2` 可能是低负载可用语音通信的平衡点；
- `L = 3` 提供最高重建质量，但负载也最高；
- `SCIT-Speech-LCA` 应在 `L = 1` 和 `L = 2` 上优于 `SCIT-Speech-Base`；
- 在轻量索引扰动下，LCA 的质量退化幅度应小于 Base。

不建议在主文中写“强信道鲁棒”。较高 BER、大规模索引错误和复杂信道编码放入 Discussion 或 Future Work。

## 7. 实验四：Baseline 对比

### 7.1 实验目的

实验四验证本文方法在通信负载和语音可用性之间的位置。它不是为了证明本文方法在所有音质指标上全面优于传统 codec，而是为了说明：在极低索引负载下，共享码本索引传输可以形成一个不同于 waveform codec 的低负载操作区间。

### 7.2 对比方法

建议至少包含三类 baseline。

**传统或工程语音编码：**

- PCM 16-bit 16 kHz，作为未压缩上界；
- Opus 或 AMR-WB，作为传统低码率语音 codec 参考；
- 若环境可行，可加入 Codec2 这类极低码率语音 codec。

注意：Opus/AMR-WB 的稳定工作区间通常高于 `500-1500 bps`。如果无法在同等码率下正常工作，应以 bitrate-quality curve 的形式对比，而不是强行设置不可用码率。

**神经音频 codec：**

- EnCodec、DAC 或同类 neural audio codec；
- 选择其公开配置中最接近的低码率点；
- 如果最低公开码率仍高于本文索引负载，应在表中明确标出。

**索引传输内部 baseline：**

- `SCIT-Speech-Base`；
- `SCIT-Speech-LCA`；
- 可选：随机索引、只传连续压缩 latent、或不共享码本的 naive variant，作为反例诊断。

### 7.3 公平对比原则

对比时同时报告：

- ideal bitrate；
- actual payload；
- 是否包含包头；
- 是否包含信道编码开销；
- 是否使用相同采样率；
- 是否使用相同测试集；
- 是否使用相同 ASR 和评价脚本。

不要只比较“模型输出听起来如何”，也不要只比较“码率数字”。本文关键是负载-可用性曲线。

### 7.4 实际传输负载核算

由于本文主张低负载通信，实验四必须同时报告理论索引负载和真实系统 payload。理论负载用于说明索引载荷的信息量下限，真实 payload 用于说明工程实现中的实际传输开销。

建议区分三类负载：

```text
ideal index bitrate
= L * latent_rate * ceil(log2 K)

packed index payload
= bit-packed indices after serialization

packetized payload
= packed indices + header + user/session id + timestamp + length fields
```

需要记录：

| Item | Meaning |
|---|---|
| ideal bitrate | 只计算离散索引本身的理论比特率 |
| packed payload bitrate | 索引经过 bit packing 后的实际字节数 |
| packetized payload bitrate | 加上包头、时间戳、用户/会话 id 后的真实传输负载 |
| overhead ratio | `(packetized payload - ideal payload) / ideal payload` |
| payload per utterance | 每条测试语音的传输字节数 |
| payload per second | 按语音时长归一化后的真实传输负载 |

对三用户系统验证，还应额外报告：

```text
single-stream payload
session-level aggregate payload
```

论文中不能只写 `500L bps`。推荐写法是：

> Under ideal fixed-length index coding, the raw index bitrate is 500L bps. In addition, we report the packetized payload including serialization and session metadata to quantify the actual transmission overhead.

### 7.5 轻量主观听感与音频样本

客观指标不能完全覆盖语音听感，因此建议加入轻量主观验证或至少发布音频样本。该部分不需要扩展成大规模人评，但应支持读者直观比较不同 `L` 和不同模型条件下的听感变化。

推荐两种执行方式：

1. **音频样本附录**：为 `L = 1, 2, 3`、Base、LCA 和若干 baseline 提供固定样本。
2. **MOS-lite 或 AB preference**：若时间允许，邀请少量听者对自然度和可懂度进行简短打分或偏好选择。

建议样本覆盖：

- clean 条件下的 `L = 1, 2, 3`；
- 轻量 index dropout / substitution 条件下的 `L = 1, 2`；
- `SCIT-Speech-Base` 与 `SCIT-Speech-LCA`；
- 至少一个传统 codec baseline；
- 至少一个 neural codec baseline，如果实验四包含 neural codec。

如果做 MOS-lite，推荐只报告描述性统计，不夸大统计显著性：

| Item | Setting |
|---|---|
| listeners | 5-10 人即可作为初步验证 |
| scale | 1-5 naturalness / intelligibility |
| samples | 每个条件 5-10 条固定语音 |
| output | mean, std, preference count |

若不做人评，至少提供音频样本索引表：

| Sample id | Original | L=1 | L=2 | L=3 | Base | LCA | Baseline |
|---|---|---|---|---|---|---|---|

### 7.6 结果呈现

推荐图表：

- `WER vs. bitrate`；
- `PESQ/ViSQOL vs. bitrate`；
- `semantic similarity vs. bitrate`；
- `payload per second`；
- `ideal bitrate vs. packetized payload bitrate`；
- 一张包含若干音频样本的主观听感表或附录链接。

预期论文表述应谨慎：

> Compared with waveform codecs that are primarily designed for signal reconstruction, the proposed index-only transmission framework provides an alternative low-load operating regime by transmitting compact codebook indices shared by the transmitter and receiver.

## 8. 实验五：消融与诊断

### 8.1 实验目的

实验五用于回答“哪些设计真的有用”。它的重点不是堆大矩阵，而是把论文中会写进贡献的设计逐一拆清楚：`L` 层码率控制是否真的有效，LCA 的鲁棒性收益来自哪些组件，语义蒸馏和 NAS 是否确实必要。

### 8.2 必做消融

**Ablation 1: NAS encoder vs. hand-designed encoder（等预算完整训练）**

```text
SCIT-Speech with hand-designed encoder
SCIT-Speech with NAS-searched lightweight encoder
```

验证 NAS 是否在保持低码率重建和可懂度的同时降低参数量、MACs、RTF 或在线延迟。当前已有 NAS profiling 结果可以支持“效率提升”，但如果论文要写“轻量化不明显损害质量”，必须补 hand-designed encoder 与 NAS encoder 的 matched-budget full retrain。若资源不足，主文只能写 NAS efficiency，不写质量等价。

**Ablation 2: Base vs. LCA**

```text
SCIT-Speech-Base
SCIT-Speech-LCA
```

验证低负载/轻量信道感知适配是否提升 `L = 1, 2, 3` 下的可用性与扰动稳定性。clean 条件下可以只期待小幅收益，重点看 index dropout/substitution 与 packet/burst loss 条件下的退化幅度。

**Ablation 3: with vs. without semantic distillation**

验证内容保留引导是否有助于最低负载条件下的 WER/CER、STOI/PESQ 和 codebook usage。当前 `distill_lambda=30` vs `0` 已有强信号；若时间允许，可补一个小 sweep：`λ_sem ∈ {0, 5, 15, 30, 60}`。

**Ablation 4: LCA 组件因子消融**

当前最重要的新增消融。至少比较：

```text
Base / full-depth training only
random-L only
ChannelSim only
random-L + ChannelSim
random-L + ChannelSim + consistency loss (full LCA)
```

验证 `random-L`、`ChannelSim` 和 `consistency loss` 各自是否必要。没有这个实验时，只能说 full LCA 有效，不能把鲁棒性收益分别归因到某个组件。

**Ablation 5: L 层贡献与截层敏感性**

报告 `L=1/2/3` 对 WER/CER、STOI、PESQ、mel-L1、speaker similarity 和 payload 的边际贡献。推荐增加 per-layer reconstruction gain、per-layer error sensitivity，以及“只替换第 m 层索引”的敏感性测试，用来支撑 `L` 是通信负载控制旋钮，而不是任意截断。

### 8.3 可选消融

**Parameter sensitivity**

小范围 sweep 即可，不建议做大网格：

```text
λ_sem: 0 / 5 / 15 / 30 / 60
λ_cons: 0 / 0.25 / 0.5 / 1.0
p_drop, p_sub: weak / default / strong
```

目的不是调出最优超参，而是说明当前设置不是随意选择，并给出适用范围。

**Multiple ASR evaluators**

如果 WER/CER 主要来自 Whisper，建议额外加入 wav2vec2/Conformer 或另一个公开 ASR，以避免“只对单一识别器友好”的质疑。

**Codebook diagnostics**

报告每层 code usage、perplexity、dead code ratio、token entropy、相近 codeword 替换 vs 随机 codeword 替换的影响。该部分支撑“离散索引可以作为通信载荷”的可解释性。

### 8.4 不建议做的消融

第一版不建议做：

- 大范围 `M` 层数搜索；
- 大范围 `K` 码本大小搜索；
- 将第一层解释成独立语义 tokenizer 的 probing 大实验。

这些实验成本高，且容易把论文主线从“共享码本索引传输的低码率语音通信方法”带偏。真实物理层联合编码、复杂 FEC 或重传协议可以写作未来工作；本文只需要覆盖到 index/packet-level 的通信化扰动边界。

## 9. 实验六：扩展测试集与跨语料验证

### 9.1 实验目的

实验六用于避免当前结果停留在 8 条 fixed samples 或同源小样本上。对于“极低码率语音通信方法”这条主线，扩展测试集和跨语料比三用户 demo 更重要。

它要回答：

- 在更大的 LibriSpeech 测试集上，`L=1/2/3` 的负载-质量曲线是否稳定；
- 在未参与训练的说话人、句子长度和声学条件上，WER/CER、STOI、PESQ 是否仍处于可用范围；
- 跨语料测试时，SCIT-Speech 的退化模式是什么；
- 当前结论是否只适用于 LibriSpeech train-clean-100 同源样本。

### 9.2 数据集与最小执行方案

推荐按成本分三档执行：

| Level | Dataset | Purpose | Required |
|---|---|---|---|
| S0 | 当前 8 条 fixed samples | 快速回归与图表生成 | 已完成 |
| S1 | LibriSpeech test-clean/test-other 子集或全量 | 大测试集稳定性 | 必做 |
| S2 | VCTK 或 LibriTTS | 跨语料泛化 | 强烈建议 |
| S3 | AISHELL-1 或中文小集合 | 跨语言边界 | 可选 |

如果算力不足，S1 至少抽取固定子集，例如每个 split 100-300 条，覆盖多个 speaker 和不同时长。所有抽样规则必须固定随机种子并保存 manifest。

### 9.3 统计口径

每个数据集至少报告：

| Metric group | Metrics |
|---|---|
| Load | ideal bitrate, packed bitrate, packetized bitrate |
| Intelligibility | WER, CER, STOI |
| Reconstruction | PESQ-WB, mel-L1, SI-SNR |
| Robustness | clean vs perturbed degradation |
| Runtime | encoder RTF, decoder RTF, end-to-end latency if available |

主表不要只给均值。建议报告 mean、std、median，以及 paired bootstrap 置信区间或按 utterance 的 paired difference。若暂时不做显著性检验，至少在文中说明结果为描述性统计。

### 9.4 论文表述边界

如果 S1 完成但 S2/S3 未完成，可以写：

> We validate the method on a larger held-out LibriSpeech evaluation set and leave broader cross-corpus and multilingual generalization to future work.

如果 S2 完成，可以写：

> We further evaluate on an out-of-domain speech corpus to test whether the low-bitrate index transmission behavior transfers beyond the training corpus.

## 10. 实验七：通信化索引与包级扰动验证

### 10.1 实验目的

现有 ChannelSim 主要覆盖 index-level dropout 和 substitution。对于低码率语音通信方法，还需要补充更接近通信链路的错误模式，但不必扩展到完整物理层系统。

实验七要回答：

- 当错误不是独立随机 token error，而是连续 burst 或 packet-level loss 时，SCIT-Speech 是否仍有可用边界；
- LCA 是否相对 Base 降低了扰动下的退化幅度；
- 哪些错误率/包长下，`L=1/2/3` 开始不可用；
- 现有 index-level ChannelSim 与 packet-level 错误之间是否存在明显 gap。

### 10.2 必做扰动

至少加入两类：

| Perturbation | Description | Why |
|---|---|---|
| Burst index loss | 连续若干 latent frames 的索引被 previous-index replacement 或 zero-order hold 替代 | 模拟连续丢失 |
| Packet loss | 按 packet 删除一段 packed indices，再由接收端 concealment | 对应真实 payload 传输 |

推荐再加入一类：

| Perturbation | Description | Why |
|---|---|---|
| Gilbert-Elliott | good/bad state 的 burst channel | 比 i.i.d. dropout 更接近网络错误 |

### 10.3 不做或降级处理

以下内容不作为本文必做：

- 真实无线物理层仿真；
- 调制、信道编码、重传协议联合优化；
- 大规模 FEC 对比；
- 高 BER 下“强鲁棒”声明。

如果补 FEC，只建议做一个轻量映射实验：给定 BER/FEC 后估计 index error rate，再套入本文 index/packet perturbation，不把它写成完整物理层贡献。

### 10.4 结果呈现

推荐图表：

- `WER/STOI/PESQ degradation vs packet loss rate`；
- `Base vs LCA robust_imp heatmap`；
- `L=1/2/3` 在 burst length 变化下的可用边界；

## 13. 当前待决策项

正式执行前需要确认：

1. 主训练路线：建议先执行实验一 NAS 搜索，再在实验二训练 `SCIT-Speech-Base`，实验三得到 `SCIT-Speech-LCA`。
2. 训练数据规模：建议先用 LibriSpeech train-clean-100 完成可复现实验。
3. 语义教师：建议固定一个内容表征模型，只作为训练辅助和评价辅助，不作为论文贡献。
4. NAS 搜索约束：建议固定 stride schedule、latent rate 和 latent dimension，只搜索 `Z` 之前的 encoder 结构。
5. NAS 选择规则：建议从 semantic preservation 与 compute cost 的 Pareto frontier 中选择主架构。
6. ChannelSim 实现：第一版建议使用合法索引替换和 previous-index replacement，避免引入 mask token 改动。
7. baseline 范围：至少 Opus/AMR-WB 或同类传统 codec，加一个 neural codec；若环境成本过高，先完成传统 codec 对比。
8. 是否做 `with/without semantic distillation`：建议做，因为它直接支撑“第一层为什么偏向语义”的设计理由。
9. LCA 组件消融：建议作为当前最高优先级补实验，拆开 `random-L`、`ChannelSim` 和 `consistency loss`。
10. payload 统计格式：建议同时输出 ideal bitrate、packed payload 和 packetized payload。
11. 扩展测试集：至少确定 LibriSpeech test-clean/test-other 是全量评估还是固定子集评估。
12. 跨语料：优先选择 VCTK 或 LibriTTS；中文 AISHELL-1 作为可选边界实验。
13. 三用户 demo：可作为系统可行性附录；若时间不足，可以删除，不影响主论文核心结论。
14. 主观听感：若来不及做人评，至少整理固定音频样本表和附录链接，并明确未做人评。

## 14. 论文写作口径

推荐写法：

> We propose SCIT-Speech, a low-bitrate speech communication method based on shared RVQ codebook index transmission. The transmitter and receiver pre-share the RVQ codebooks, model parameters, and system configuration; at runtime, the channel carries only discrete codebook index sequences. By transmitting the first L RVQ layers, SCIT-Speech operates at approximately 500, 1000, and 1500 bps. We evaluate its load-quality trade-off, index-level robustness, payload overhead, and lightweight transmitter design against conventional and neural codec baselines.

中文解释：

> 本文提出 SCIT-Speech，一种基于共享 RVQ 码本索引传输的极低码率语音通信方法。发送端与接收端预先共享 RVQ 码本、模型参数和系统配置；运行时信道仅传输离散码本索引序列。通过传输前 `L` 层 RVQ 索引，SCIT-Speech 可在约 500、1000 和 1500 bps 三个工作点之间切换。本文围绕负载-质量权衡、索引扰动鲁棒性、真实 payload 开销和轻量发送端设计，与传统 codec 和神经 codec 进行系统比较。

避免写法：

> We use an existing speech tokenizer as our method.

避免原因：

- 它会把论文贡献误导为具体开源 tokenizer 应用；
- 它弱化了共享码本索引传输方法本身；
- 它会让审稿人把本文当成已有 tokenizer 的下游实验，而不是低码率语音通信方法论文。

## 15. 执行顺序

建议按以下顺序执行。已完成的实验可直接标记为 done，后续优先补高价值缺口：

1. 准备 NAS 搜索子集和搜索空间。
2. 执行实验一 NAS 搜索，选定轻量化语义提取 encoder。
3. 确认 `SCIT-Speech-Base` 配置和训练脚本。
4. 完成实验二基础训练与 sanity check。
5. 统计 layer-wise codebook usage、perplexity 和 dead code ratio。
6. 实现 `L = 1, 2, 3` 截层解码评估脚本。
7. 实现实验三低负载/轻量信道感知适配。
8. 跑 Base vs. LCA 主评估。
9. 跑实验四 baseline 对比。
10. 统计 ideal bitrate、packed payload 和 packetized payload。
11. 跑实验五必要消融，优先补 LCA component factorial ablation。
12. 补 LibriSpeech test-clean/test-other 大测试集评估。
13. 补 VCTK 或 LibriTTS 跨语料评估。
14. 补 burst loss / packet loss / Gilbert-Elliott 扰动评估。
15. 整理固定音频样本或 MOS-lite / 人工可懂度结果。
16. 视时间决定是否整理三用户 demo 数据；若没有完成，删出主实验路线。
17. 汇总表格、曲线和音频样本。
18. 将结果回填到论文 Experimental Setup 和 Results。
