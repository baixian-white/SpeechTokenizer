# 六用户语音通信与说话人身份识别 Demo：实验指标及数据交付要求

日期：2026-09-24  
用途：交给负责实现 Demo 的同学，作为实验设计、数据采集和最终交付依据。  
状态：实验要求建议稿。本文不包含新实验结果，也不预设准确率、延迟等指标必须达到某个数值。

## 1. 任务目标

在原三用户中心路由语音通信 Demo 的基础上，扩展为六用户，并接入另一分支已经完成实验的 Exp23 说话人身份识别模型。

最终交付不能只有“程序能运行”、界面截图或演示视频，还需要能够支撑论文的原始测量记录、汇总结果和复算方法。

本次系统实验主要回答四个问题：

1. 六用户是否能够稳定通信，每个接收端是否正确处理其他用户的数据流？
2. 经过实际分块、传输和接收处理后，重建语音质量如何？
3. 接收端能否根据接收索引及重建语音正确识别说话人，多久输出或更新身份？
4. 从三用户扩展到六用户、以及增加身份识别后，延迟、计算资源和通信量如何变化？

**核心交付原则：每个论文数字都应能追溯到具体实验配置和原始记录。结果不理想也应如实交付，不得通过删除失败运行、挑选说话人或更换统计分母美化结果。**

## 2. 沿用的模型与接口

| 项目 | 本次沿用的设置或约束 |
| --- | --- |
| 通信结构 | 原三用户中心路由结构，扩展到六个客户端 |
| 语音编解码器 | 与正式说话人实验匹配的 SCIT-LCA 检查点；附录记录为第 30,000 步保留模型 |
| 语音工作点 | 16 kHz 单声道，三层 RVQ，即 `L=3` |
| 说话人模型分支 | `feature/exp23-speaker-classifier` |
| 已知模型位置 | `D:\tmp\speechtokenizer-exp23\tmp\exp23_formal\export\seed42_bundle`，这是当前机器位置，交接后应配置实际路径 |
| 分类器输入 | 同一输入流、同一时间区间的接收索引和对应重建波形 |
| 分类器结构 | Token 分支与音频分支分别产生 256 维特征，经门控融合和分类头输出身份 |
| 正式训练状态 | SCIT-LCA 和 ECAPA 主干冻结；Token 编码器、音频投影、融合模块和分类头参与训练 |
| 交付模型 | seed42，连同标签映射、预处理配置和温度校准文件一起加载 |
| 默认通信块 | 0.5 秒；分类窗口与通信块不是同一个概念 |
| 默认识别设置 | 三秒窗口，每新增一秒解码语音更新一次 |
| 输入配对 | 根据实际音频长度与索引长度配对，不对所有三秒窗口一律硬截成 150 帧 |
| 身份推理位置 | 接收端逐流识别，在播放混音之前执行 |
| 身份信息传输 | 不额外传输说话人特征向量；客户端编号不作为分类器输入 |

当前正式模型输出固定的 110 个 VCTK 身份。**六个通信用户不等于把模型改成六分类。** 直接沿用交付模型时，应保留原 110 类输出和概率校准；如果限制为六个候选身份，需要作为改变后的另一实验条件单独报告。

若本次使用六位未被模型训练过的新同学，需要另外完成身份注册或模型适配。该结果不能与原 110 类闭集实验混为一谈，也不能仅通过修改 `user_id` 实现新身份识别。

现有论文中三种子平均 Top-1 为 94.93%，seed42 的正式测试 Top-1 为 94.18%。这些是已有闭集实验结果，**不是本次六用户在线实验的结果或必须达到的验收门槛**。

除明确不适用的项目外，以下八组指标均应交付。缺失项目应写明原因，不得填写估计值冒充实测值。

| M2 | 接收语音质量 | STOI、PESQ-WB、mel-L1，逐语句结果及汇总均值 | 保存每路混音前重建音频，与对应原始音频比较；沿用论文指标设置，记录分块、补齐及对齐规则 |

| M7 | 实际通信量 | 每路语音载荷码率、应用层总码率、各客户端上下行流量、路由器总流量 | 区分索引载荷、应用层包头、传输层或链路层流量；分开报告发送和接收，避免重复统计 |

### 3.1 在线身份识别的分母

正式运行前，依据发送源时间轴和预定窗口策略，确定“应当产生预测”的窗口集合。不能用接收端最终是否成功形成窗口来反向决定分母，否则通信失败会被隐藏。

设：

- `N_expected`：按预定协议应产生预测的窗口数。
- `N_predicted`：实际产生有效预测的窗口数。
- `N_correct`：有效预测中身份正确的窗口数。

分别报告：

```text
已输出预测中的 Top-1 = N_correct / N_predicted
预测覆盖率           = N_predicted / N_expected
端到端正确输出率     = N_correct / N_expected
```

分母为零时写为不适用，并保留原始计数，不能自动填为零分或满分。

每人准确率应注明采用上述哪种分母。Macro-F1 的类别集合及无输出处理规则也须注明：建议主表报告以全部应预测窗口计算的六个真实身份 Macro-F1，预测到其他身份和无输出均构成对应真实身份的漏识别；可另附仅基于有效预测的 Macro-F1。

用于展示的混淆矩阵可以是六行、八列：六个真实身份对应六行，预测列为六个演示身份、“其他已训练身份”和“无输出”。同时保留原始 110 类预测标签，不能把预测到其他 104 类的错误删除。

三秒初始化阶段、短于窗口的语句、静音、跨说话人窗口以及切换过渡段如何处理，必须在正式测试前写入协议。初始化等待计入首次识别耗时；即使某类窗口不进入稳态准确率，也要交付其数量和原因。

### 3.2 延迟与实时性

- 通话延迟和身份识别延迟分别报告。三秒分类窗口不等于三秒语音播放延迟。
- 记录分块的采样范围，明确延迟是相对于块首样本、块尾样本还是其他事件测量，所有对照保持一致。
- 端到端通话测量应覆盖采集、分块等待、编码、网络、接收队列、解码及播放等待；不能仅将各阶段不同时刻的均值相加，冒充逐次测得的端到端分布。
- 跨机器时间戳需要同步方法和误差记录。缺少可靠同步时，应使用共同采集设备测输入输出，或将结论限定为可可靠测量的局部耗时；不能直接用 RTT 除以二代替实测单向延迟。
- 播放回调被调用，不一定等于声音已经由设备输出。报告测量所到达的实际边界；关闭播放的运行不能用于宣称完整通话播放延迟。
- 首次或切换后的“正确识别”应预先定义为单次正确输出，或连续若干次正确输出，并同时记录始终未正确识别的比例，不能只统计成功案例。
- 即使编码器或解码器的单次 RTF 小于 1，也要检查六用户负载下队列是否持续增长、播放是否欠载以及预测是否按时更新。

### 3.3 质量、流量与丢失

- 质量评价针对单路接收重建，不把多路混音与某一个人的原始音频比较。保留真实缺失造成的时间空隙或按预定规则进行补偿，不能删除困难片段后评分。
- 每条源语句及其多个接收副本保留关联。建议先在同一源语句的接收副本间汇总，再逐语句等权汇总，同时交付逐接收端结果。
- 指标无法计算时保留失败原因和计数，不得静默跳过。延迟分位数针对成功观测时，也须同时报告未到达、超时和失败比例。
- 1.5 kbit/s 是名义索引码率。按附录的 0.5 秒块打包时，94 字节对应 1.504 kbit/s 的字节对齐载荷，尚未包含全部协议开销。
- 日志计算出的应用层字节数不应直接称为完整链路流量。若没有抓包或网络计数器证据，应明确测量只覆盖到应用层。
- 区分未收到、接收队列丢弃、解码失败、播放前过期等情况，并提前确定等待或播放期限。论文中的索引域扰动不能自动视为真实网络丢包。

## 4. 最小实验对照

| 组别 | 设置 | 主要目的 |
| --- | --- | --- |
| A | 同一批音频，本地分块编解码与 Exp23 识别，不经过网络 | 测量与 Demo 相同分块策略的本地基准，区分分块影响与网络影响 |
| B | 三用户通信，开启 Exp23 识别 | 建立较小并发规模下的系统基准 |
| C | 六用户通信，关闭身份识别 | 测量六用户通信本身的质量、延迟、流量与资源开销 |
| D | 六用户通信，开启 Exp23 识别 | 测量完整系统表现，并与 B、C 对照 |

执行要求：

1. 六用户实验分别包含轮流说话和六路同时发送语音的场景。记录“连接人数”和“同时活跃的发送路数”，二者不能混用。
2. 三用户组可分两批覆盖同一批六位说话人，尽量保持音频内容、播放速度、硬件和网络条件可比。
3. 每组建议至少独立重启、重复三次，每次完成提前确定的音频清单；另进行一次至少 30 分钟的六用户并发稳定性测试。这是最低工程测量建议，不代表对所有论文结论都具有充分统计效力。
4. 六进程在一台机器运行、六台设备跨局域网运行，应作为不同部署条件。不能用单机回环结果替代跨机系统验证；在共享硬件上运行时，交付机器总资源和可取得的进程级资源。
5. A、B、D 使用相同分类器、预处理、温度和预测策略。B 不能沿用旧的 ECAPA/MFCC 匹配结果，冒充与 Exp23 的规模对照。
6. 正式测量前先用开发音频调通系统，随后冻结实验清单与配置。选取六人不能以“谁的测试准确率高”为依据；测试语句不得参与模型训练、阈值调整或故障调参。
7. 若直接使用现有 VCTK 身份，可使用选定六人的保留测试语句开展系统测试，并明确这是一组六人子集实验，不是重新证明完整 110 人总体性能。

## 5. 统计与报告约定

- 每次运行分别报告，再给出跨运行均值和标准差。时间分布至少报告中位数与 P95；注明是逐次计算后汇总，还是合并全部观测计算。
- 重复回放相同音频主要检验运行重复性，不增加独立语音样本数，也不等于训练了多个新模型。
- 同一语句发送到五个接收端，以及同一语音上的重叠窗口，均保留分组关系。不能把这些记录全部当成独立样本来缩窄置信区间。
- 后续计算置信区间时应依据源语句、说话人或会话的实际分组结构选取方法，记录重采样单位、次数及随机种子，并说明结论针对所选六人还是更大总体。
- “三次系统运行的标准差”与现有论文“三个训练种子的标准差”是不同统计量，表头和正文必须区分。
- 需要设置延迟上限、稳定识别规则或拒绝阈值时，应在正式测试前确认并保存；不得看到测试结果后调整规则再只报告有利结果。
- 不要求复现某个预设高分。协议执行完整、数据真实可复算，与系统是否达到预设工程性能目标，是两项不同的验收结论。

## 6. 可选增强实验与有条件必做项

| 项目 | 优先级 | 需要交付的内容及限制 |
| --- | --- | --- |
| 网络扰动 | 可选增强；若声称实际网络鲁棒性则需要 | 明确扰动层、工具、强度和实际观测情况；分别报告延迟、质量与识别退化，不把 token 掩码直接叫作网络实测丢包 |
| 识别窗口比较 | 可选增强 | 比较窗口长度带来的准确率与响应时间变化；主结果继续保留既定三秒设置，其他窗口独立标注 |
| 旧识别方法对照 | 可选增强 | 用同一批音频比较旧匹配方式与 Exp23；注明模型、注册与预测规则，不能混用不同实验数据 |
| Token/audio/fusion 比较 | 可选研究增强 | 单独设计、报告分支比较；辅助头直接推理不自动等价于独立训练的单分支消融 |
| 新用户注册或适配 | 六人为未训练身份时必需 | 单独记录注册、训练、开发与测试数据，说明采用何种身份输出机制；不能直接沿用固定 110 类标签冒充新身份 |
| 身份认证 | 论文保留“身份认证”主张时必需 | 设计真实身份与冒充身份试验，报告固定阈值下误接受率、误拒绝率及试验数；补充 DET 或 EER；阈值由独立开发数据确定 |

身份识别回答“在已知类别中是谁”，身份认证还要验证某个声称身份是否成立。闭集 Top-1、模型最大概率或界面中的 `verified` 标志，不能直接作为可靠认证或未知说话人拒识的证据。

如需声称抗录音重放或其他攻击能力，还需要对应攻击试验，不能仅凭上述身份认证指标推断。论文若涉及真实量子链路，其测量应由相应实验另行提供，不能从本软件 Demo 的通信统计推算。

| `figures/` | 最终图表及其来源数据，不仅提供截图 |

CSV 中没有观测到的值应留空或使用明确的缺失标记，并配合状态列。不能把“未测量”写成零，不能只写汇总数字而丢弃逐条记录。

资源采样建议固定间隔，例如一秒一次，并把实际间隔写入配置。时间戳应注明时钟类型、单位及设备；跨设备可比时间与进程内单调计时应分别保存，不能直接混减。

## 9. 现有 Demo 的统计注意事项

现有主工作区三用户 `group_client.py` 中已有部分计数和 CSV 导出，可复用结构，但不能直接视为本次实验已经具备完整统计能力：

1. `one_way_latency_budget_ms` 由分块时长与目标缓冲时长相加得到，是配置预算，不是端到端实测延迟。
2. 旧的识别正确性判断直接比较 `prediction.predicted_speaker` 与 `stream.sender_id`。新实验应使用独立的音频身份清单进行评分，尤其是同一流切换说话人的测试。
3. 旧的 `drop_rate` 不能未经核对就称作网络丢包率，需要确认计数来源并补充分母、期限和失败分类。
4. 只有汇总 CSV 不足以复核窗口配对、身份真值与延迟，需要补充第 7 节的逐条数据。
5. 修改以上测量逻辑后，应先用可控制的短音频和已知事件检查统计是否正确，再进行正式运行。
