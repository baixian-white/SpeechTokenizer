# 六用户低码率语音通信与 Exp23 说话人识别实验报告（GPU 版）

**报告日期：** 2026-10-08  
**实验条件：** D：六用户、Exp23 识别开启；A–F 映射为 `p225`、`p226`、`p227`、`p228`、`p229`、`p230`   
**通信设置：** 16 kHz、单声道、三层 RVQ、0.5 s 通信块；识别采用既定三秒上下文和 110 类 seed42 Exp23 bundle。  
**部署架构：** 六个轻量客户端 + Router + 一个共享 GPU Worker；LCA 编码/解码集中运行在 GTX 1650 `cuda:0`。Exp23 TorchScript bundle 因 CPU 常量与 CUDA 张量混用，当前在 Worker 内使用 CPU 回退分类器。  
**指标依据：** `six_user_demo_metrics_requirements_20260924.md` 的 M1–M8。  
**延迟边界：** 采集/回放调度到解码完成；扬声器关闭，因此不报告完整声学输出延迟。

## 1. 数据与可复算入口

本报告使用 GPU 项目中的三组最新完整运行：

- **正式 D 轮流发送：** [system_metrics_20261007_131923](../results/gpu/system_metrics_20261007_131923)，每个身份 15 条测试语音，6 个发送源依次运行。
- **正式 D 同时发送：** [system_metrics_20261007_133107](../results/gpu/system_metrics_20261007_133107)，每个身份 15 条测试语音，6 路同时发送。
- **最新 30 分钟稳定性：** [system_metrics_20261007_133535](../results/gpu/system_metrics_20261007_133535)，六路同时发送，源回放时长 1800 s。

三次运行的 `run_manifest.json` 均记录 `torch==2.11.0+cu128`、`torchaudio==2.11.0+cu128` 和 GTX 1650 4 GiB；运行状态为 `complete`，`failures.json=[]`。运行保留 `summary.csv`、`per_stream_metrics.csv`、`per_speaker_metrics.csv`、`predictions.csv`、`blocks.csv`、`audio_metrics.csv`、`resources.csv`、`traffic.csv`、`events.csv` 和 `confusion_matrix.csv`。

身份识别分母固定为：

```text
有效预测 Top-1       = N_correct / N_predicted
预测覆盖率           = N_predicted / N_expected
端到端正确输出率     = N_correct / N_expected
```

报告中的同时发送和稳定性结果必须同时查看覆盖率与端到端正确输出率，不能只看有效预测中的 Top-1。

## 3. CPU 与 GPU 的直接对照

| 场景 | CPU 结果 | GPU 结果 | 变化 |
|---|---:|---:|---|
| 轮流发送：Top-1 | 85.56% | 85.56% | 分类精度基本不变 |
| 轮流发送：覆盖率 | 100% | 100% | 均完整 |
| 轮流发送：编解码 P95 | 编码约 234 ms、解码约 526 ms（CPU 正式重复中的高值） | 编码 15.18 ms、解码 18.71 ms | GPU 显著降低单块编解码时间 |
| 同时发送：解码块 | 614/2700（CPU 单次正式） | 1527/2700 | GPU 提升并发处理能力 |
| 同时发送：覆盖率 | 约 2.44%（CPU 三次均值） | 16.44% | GPU 有明显改善但仍不足 |
| 同时发送：端到端正确率 | 约 2.44%（CPU 三次均值） | 14.44% | GPU 有明显改善但仍非实时可用 |
| 30 分钟：解码块 | 19014/108000 | 57194/108000 | GPU 提升到约 52.96% |
| 30 分钟：预测覆盖率 | 2.35% | 2.89% | 分类回退和满载排队仍限制覆盖 |

GPU 的优势主要体现在 LCA 编码和解码，轮流发送的识别结果与 CPU 基线一致，说明迁移没有改变模型判别行为。并发时 GPU 降低了单块计算时间，但共享 Worker 的串行化请求、六路任务积压以及 CPU 上的 Exp23 推理仍然使“采集到解码”达到 10 秒量级。

## 4. 科研分析与结论

GPU 版本已经证明：在 GTX 1650 4 GiB 上，通过“一份共享 LCA GPU Worker + 六个轻量客户端 + Router”的架构，可以完整运行六用户通信实验，显存峰值约 1.16 GiB，30 分钟内没有进程崩溃或 TCP 断连。轮流发送条件下，2700 个通信块全部收到并解码，450 个身份窗口全部产生预测，Top-1 为 85.56%，音质指标与 CPU 基线一致。

同时发送和稳定性测试显示，GPU 版仍未达到六路实时满载的工程目标。GPU 可以把正式同时发送的解码完成块从 CPU 的 614 个提高到 1527 个，把稳定性解码比例从约 17.61% 提高到约 52.96%，但大量块仍超过期限或在接收队列中丢弃。稳定性中有效预测 Top-1 为 87.95%，而覆盖率只有 2.89%，因此系统级身份识别结果应以端到端正确输出率 2.54% 和覆盖率为主。

当前结论应写为：**GPU 版适合作为六用户轮流发送的完整实验平台，并明显改善六路并发的编解码吞吐；在 Exp23 仍为 CPU 回退、共享 Worker 使用当前队列策略的情况下，六路同时发送和 30 分钟满载尚未达到实时处理要求。** 这项结论来自实际 M1–M8 记录，不等同于离线 Exp23 的 110 类 Top-1 结果。

## 5. 限制与后续工作

1. GPU 正式轮流和同时发送目前各有 1 次完整运行，30 分钟稳定性也有 1 次；应继续做独立重启重复，以得到系统运行均值和标准差。
2. Exp23 bundle 当前不能直接安全迁移到 CUDA，报告中的 `gpu_worker` 是 GPU LCA 编解码 + CPU 分类回退，不能称作全模型 GPU。
3. 当前没有同一流内真实说话人切换，M5 的切换后正确识别耗时和切换失败次数为未测。
4. 播放关闭，播放欠载为 0 仅表示没有启用声学输出回调，不能推出实际扬声器播放稳定。
5. 下一步应优先重新导出设备安全的 Exp23 bundle，或把分类请求做批处理/独立 CPU 线程池，并对 Worker 队列设置背压和按期限丢弃策略；修改后应重新运行 D concurrent 和 30 分钟 stability。
