# 六用户低码率语音通信与 Exp23 说话人识别实验报告（CPU 版）

**报告日期：** 2026-10-08  
**实验条件：** D：六用户、Exp23 识别开启；A–F 映射为 `p225`、`p226`、`p227`、`p228`、`p229`、`p230`   
**通信设置：** 16 kHz、单声道、三层 RVQ、0.5 s 通信块；识别采用既定三秒上下文和 110 类 seed42 Exp23 bundle。  
**指标依据：** `six_user_demo_metrics_requirements_20260924.md` 的 M1–M8。  
**部署条件：** 单机 TCP loopback；CPU 基线。麦克风和扬声器关闭，因此延迟边界是“采集/回放调度到解码完成”，不是声学播放延迟。

## 1. 数据与可复算入口

本报告把两类运行分开解释：

- **正式 D 条件：** [system_metrics_20260929_131012](../results/cpu/system_metrics_20260929_131012)，D 条件轮流发送和同时发送各重复 3 次，使用每个身份 15 条测试语音。
- **最新 30 分钟稳定性：** [system_metrics_20260929_172118](../results/cpu/system_metrics_20260929_172118)，六路同时发送，源回放时长 1800 s。

每次运行均保留 `run_manifest.json`、`summary.csv`、`per_stream_metrics.csv`、`per_speaker_metrics.csv`、`predictions.csv`、`blocks.csv`、`audio_metrics.csv`、`resources.csv`、`traffic.csv`、`events.csv`、`confusion_matrix.csv` 和完整日志。两次作为本报告依据的运行 `failures.json` 均为空，运行状态为 `complete`。

身份识别的分母遵循要求文件：

```text
有效预测 Top-1       = N_correct / N_predicted
预测覆盖率           = N_predicted / N_expected
端到端正确输出率     = N_correct / N_expected
```

因此，同时发送时即使有效预测中的 Top-1 较高，低覆盖率仍会显著降低端到端正确输出率。

三次轮流发送的 Top-1、覆盖率、Macro-F1 和质量均值完全一致，说明在当前固定回放清单下结果具有较好的重复性；这三次是系统重复，不是三个训练随机种子。

### 2.2 同时发送（3 次重复）

三次重复的身份指标均值为：有效预测 Top-1 **96.30% ± 6.42 个百分点**，预测覆盖率 **2.52% ± 0.46 个百分点**，端到端正确输出率 **2.44% ± 0.59 个百分点**，Macro-F1 **0.0458 ± 0.0114**。以第 3 次重复为例：450 个应预测窗口中仅产生 13 个预测，2700 个通信块中 607 个完成解码，1286 个超过期限，807 个被接收队列丢弃；采集到解码 P95 为 10.86 s，STOI 为 0.1873，PESQ-WB 可计算 220/450 条，mel-L1 为 8.6390。

这说明 CPU 版的分类器本身在少量有效重建窗口上仍能给出正确结果，但六路同时发送时处理能力不足，通信块和识别窗口无法按时形成。把 96.30% 作为“在线识别率”会掩盖 97.48% 的预测缺失，因此正式结论应以覆盖率和端到端正确输出率为主。

## 3. 科研分析

CPU 版建立了一个清晰的两段式基线。轮流发送时，六用户 Router、三层 RVQ 和 Exp23 分类器能够完整处理 450 个识别窗口，语音质量和识别率可复现；三次重复的系统方差为零，说明固定数据清单下编解码和分类链路稳定。该结果可以作为六用户系统的离线/低并发基准。

同时发送和 30 分钟稳定性揭示了真正的扩展瓶颈：应用层收包没有缺失，然而 CPU 编码、解码、音频质量计算和分类任务共享有限计算资源，接收队列达到 64，块在期限内无法完成。稳定性中“有效预测 Top-1 88.01%”与“覆盖率 2.35%”的差距说明瓶颈首先是实时调度和重建覆盖，其次才是分类器判别错误。

因此，CPU 版的科研结论应写为：**六用户路由通信在轮流发送条件下可复现并完成识别；六路同时发送能够保持 TCP 收包，但在当前单机 CPU 资源下无法维持规定的实时解码和识别覆盖率。** 不能把 CPU 稳定性结果表述为六用户实时通信已经满足要求。

## 4. 限制与后续实验

1. 当前报告只有一次 30 分钟稳定性运行；正式 D 条件虽有三次系统重复，但仍应在论文中区分“系统重复”和“训练种子重复”。
2. 当前 D 运行没有同一流内说话人切换，因此 M5 的切换后正确识别耗时和切换失败次数为未测。
3. 播放设备关闭，所有播放欠载计数为 0 只表示没有启用播放回调，不能推出声学输出稳定。
4. 稳定性质量指标包含大量过期/缺块样本，正式报告中应同时给出失败计数，不能只引用均值。
5. 若要研究六路同时发送，应优先使用 GPU Worker 版本或减少每路客户端的重复模型与质量计算，再重新测量 D concurrent 和 30 分钟稳定性。
